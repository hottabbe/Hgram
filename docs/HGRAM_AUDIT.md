# Hgram: проверка кода, брендинга и Android-конфигурации

## Область проверки

Проверены текущие исходники hgram, существующие JVM/Robolectric-тесты основного
модуля, загрузчики моделей, пути обновления приложения, ресурсы запуска,
название в обоих заголовках списка чатов и разрешения собираемого APK.
Это не утверждение о полном тестовом покрытии Telegram: UI, датчики, MediaCodec,
Vosk/sherpa JNI и сетевое скачивание моделей требуют проверки на Android.

## Исправления

- `HgramContentHeuristics`: учтены падежные формы «скидкой», «скидки» без двойного
  начисления баллов за несколько форм одного слова. Существующий тест рекламного
  призыва со ссылкой теперь проходит.
- `HgramConfig.reset()`: сбрасывает также активное состояние приватного режима.
- Vosk: сохраняются промежуточные завершённые сегменты, а не только последний
  `getFinalResult()`. Задачи распознавания выполняются последовательно; модель
  закрывается после использования, постоянный кэш нативных моделей удалён.
- После успешного и неуспешного распознавания снимается состояние занятости
  `TranscribeButton`. Исправлена выдача PCM для частот ниже 16 кГц.
- Загрузчики Vosk и sherpa: защита от повторного скачивания одной модели,
  установка через временный каталог, проверка обязательных непустых файлов,
  очистка временных файлов и закрытие HTTP-соединений при ошибках.
- Распаковка ZIP проверяет выход за пределы каталога; TAR также отклоняет ссылки
  и специальные записи. Добавлены регрессионные тесты ZIP и неполной модели.
- Убрана отложенная очистка `MessageObject` после закрытия чата: объект мог уже
  использоваться повторно в новом экране. Очистка при нехватке памяти больше не
  уничтожает изображения открытых статей и списки выбранных медиа.

## Брендинг и сборка

- Название приложения — **Hgram**, включая обычный заголовок и заголовок при
  показе историй. Старые стандартные значения `Nagram`/`hgram` отображаются как
  `Hgram`; пользовательские названия сохраняются.
- Новая иконка: белая H с элементом облачка на бирюзовом фоне. Для Android 8+
  используется adaptive icon, для старых версий — vector drawable.
- Новый экран запуска: общая символика на старых Android и системном splash
  Android 12+, включая ночную тему. Старая неиспользуемая анимация удалена.
- Однократная миграция включает новую стандартную иконку после обновления.
- `versionName` остаётся **13.0.2**, `versionCode` повышен **1255 → 1256**.
  Пакет остаётся `org.hgram`, выходной файл начинается с `Hgram`.

## Обновления

У Hgram нет собственного update feed. Проверка при запуске/возобновлении,
прямые вызовы старого `UpdateHelper`, отображение сохранённого предложения
обновиться и пункты проверки/канала обновлений отключены. Старое сохранённое
предложение сбрасывается. Это не отключает обновления языков, стикеров и моделей.

## Разрешения

Удалены из основного манифеста:

- `READ_CLIPBOARD`, `android.permission.INSTALL_SHORTCUT` — неработающие
  декларации для обычного приложения;
- `MANAGE_ACCOUNTS`, `AUTHENTICATE_ACCOUNTS`, `READ_PROFILE` — старые декларации,
  не требуемые текущими AccountManager/контактными сценариями на minSdk 23;
- старое signature-разрешение `MAPS_RECEIVE`;
- `READ_GSERVICES` — устаревшее разрешение. Удаляется также через
  `tools:node="remove"`, поскольку зависимость добавляет его обратно;
- package-visibility query системного `RecognitionService`: распознавание
  теперь идёт локально через Vosk/sherpa.

Ограничены `READ_EXTERNAL_STORAGE` до API 32, `BLUETOOTH` до API 30.
Bluetooth объявлен необязательной аппаратной возможностью.

Оставлены разрешения действующих возможностей: сеть/push/фоновые сервисы,
камера и микрофон, галерея/аудио, контакты/синхронизация, местоположение и его
фоновая отправка, звонки/Bluetooth/PiP-окна, биометрия, уведомления/бейджи,
ярлыки и платежи. `REQUEST_INSTALL_PACKAGES` нужен также для открытия APK из
вложений (`AndroidUtilities.openForView`, `ApkInstaller`), независимо от updater.

## Ресурсы

`node Tools/hgram-audit.mjs` выполняет статическую инвентаризацию:

- обработано 3617 Java/Kotlin/XML-файлов на момент проверки;
- дубликатов деклараций в проверяемых values-файлах не найдено;
- у всех `Hgram*`-ресурсов найдены ссылки;
- обнаружены runtime-поиски ресурсов. Поэтому отсутствие буквальной ссылки
  не является основанием для массового удаления остальных ресурсов Telegram.

Скрипт печатает также разрешения и результаты последнего прогона тестов.
Это дополнение к Android resource compiler, а не замена полноценного Lint.

## Проверки

1. Первый запуск hgram: 12 тестов, одна логическая ошибка (рекламный призыв).
2. Полный запуск существующего набора: 43 теста, 38 успешных, 5 ошибок среды:
   `OpenCCTest.ccTest`, `DnsFactoryTest.testDns` и три `InputTextAnimationTest`.
   Первые два требуют Android JNI, последние — нативной графики Robolectric,
   не поддерживаемой на Linux/aarch64.
3. После исправлений добавлены 4 регрессионных теста. Доступный набор: **42/42**,
   в том числе **16/16 hgram**. Нативные тесты не удалялись и не помечались
   фиктивно успешными.
4. Java/Kotlin-компиляция и debug APK собираются. Подпись проверяется `apksigner`;
   название/пакет/build/иконка — `aapt2 dump badging` уже готового APK.
5. `lintDebug` запущен, но `lintAnalyzeDebug` завершился с `Java heap space`
   при доступном Gradle heap 3 ГБ. Полный Lint-отчёт не получен.

HTML-результаты тестов: `TMessagesProj/build/reports/tests/testDebugUnitTest/index.html`.
Локальная перепроверка:

```sh
./gradlew :TMessagesProj:testDebugUnitTest --tests '*Hgram*' \
  --tests '*AndroidEnvironmentSmokeTest' --tests '*UserConfigAccountLimitTest' \
  --tests '*CarVoiceAttachmentTest' --tests '*FilterTabsViewTest' \
  --tests '*DialogsRecentForwardHelperTest' --tests '*LLMTranslatorTest'
./gradlew :TMessagesProj:compileDebugJavaWithJavac :TMessagesProj:compileDebugKotlin :TMessagesProj:assembleDebug
node Tools/hgram-audit.mjs
```

## Дальнейшее покрытие

Текущие тесты не проверяют пиксельную отрисовку карусели, жест приватности,
звонки/камеру и реальное распознавание речи. Их состояние нельзя вывести из
успешной JVM-компиляции. Дополнительно заслуживают отдельной работы потоковая
обработка PCM (сейчас длинная запись декодируется целиком в память) и
отмена/возобновление загрузок моделей с переживанием пересоздания экрана.
