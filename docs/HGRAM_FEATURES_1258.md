# Hgram 13.0.2 (1258)

## Иконки

Все 10 вариантов в штатном выборе иконок заменены. Первые три — векторные
интерпретации присланного эскиза: «Синяя H», «Тёмно-синяя H», «Оригинальная H».
Дополнительные стили: Мята, Неон, Графит, Закат, Полночь, Аметист, Пиксель.
Сохранены ComponentName alias'ов, поэтому выбранная иконка переживает обновление.
Базовая иконка и splash используют новую наклонную H с самолётиком.
Неактивные старые Turbo/Nox alias'ы тоже ссылаются на новые изображения.

## Загрузки

В настройках Hgram — фирменный делённый слайдер 1–16, по умолчанию 4, внутри
карточки сетевых настроек. Значение сохраняется и
применяется при старте загрузки обычного файла. Это число параллельных запросов
чанков на файл, а не количество Java Thread или отдельных TCP-соединений.

Используется существующий FileLoadOperation: разбиение на диапазоны, запись по
смещениям, проверка CDN и докачка не переписаны. Зашифрованные файлы, истории,
приоритетный streaming/preload и серверный fallback LIMIT_INVALID сохраняют
специальную политику. Лимиты Telegram и провайдера не обходятся гарантированно.

## Короткие сообщения

Опция выключена по умолчанию. Цепочка: 3–12 входящих текстов подряд от одного
отправителя, минимум два сообщения, каждое не длиннее 6 слов / 160 символов,
с общим окном до 10 минут. Список сообщений перед анализом нормализуется по времени,
поэтому порядок загрузки истории не влияет на результат; визуальные разделители
дат пропускаются.
Текст показывается хронологически в одном пузыре. Тап разворачивает оригиналы,
тап на сообщении развёрнутой цепочки сворачивает её. Прокрутка и долгое нажатие
отличаются от тапа по времени/движению.

Не объединяются медиа, пересылки, ответы, защищённые сущности и сообщения с реакциями,
закреплённые и подсвеченные сообщения. Отключено в секретных чатах, каналах,
специальных поисковых режимах и при включённых regex-фильтрах/скрытии блокированных.
Разделитель даты или другой отправитель разрывает цепочку. В режиме выделения
показываются исходные сообщения. БД, ID, messageOwner и серверная история не меняются.

Группы пересчитываются при обновлении списка; getItemViewType только читает
готовую карту. Лимит 12 не позволяет накапливать неограниченный пузырь.

## Голос: реализованные профили

Общий селектор заменяет прежний переключатель. Профиль фиксируется при начале
записи, применяется к голосовым сообщениям и кружкам; звонки не затрагиваются.
Состояние каждого процессора принадлежит своей записи.

| Профиль | Реальная обработка |
|---|---|
| Выключено | PCM не изменяется приложением. UNPROCESSED при поддержке, иначе MIC |
| Базовый | RNNoise из уже включённой нативной библиотеки, 480 отсчётов при 48 кГц |
| Ультра | Потоковый GTCRN через sherpa-onnx/ONNX Runtime, с линейной адаптацией частоты и мягким автоуровнем |
| Студия | DPDFNet 48 кГц → консервативный мастеринг; Opus 64 кбит/с для ГС, AAC 128 кбит/с для кружков |

Мастеринг — удаление НЧ-гула, мягкое добавление ВЧ-гармоник, компрессия и лимитер.
Вместо одиночного общего DSP-состояния используются независимые сессии.
Для моделей есть bounded PCM FIFO с линейной интерполяцией, краткий underrun
удерживает уровень и плавно возвращается без нулевого провала; тихий выход Ultra
поднимается ограниченным автоуровнем. Модели вычисляются в потоке записи.
Неудачный старт нейросети явно переводит эту запись на базовую обработку.

Модели скачиваются при выборе профиля, в APK не включены. Источник:

- `https://github.com/k2-fsa/sherpa-onnx/releases/download/speech-enhancement-models/gtcrn_simple.onnx`
- `https://github.com/k2-fsa/sherpa-onnx/releases/download/speech-enhancement-models/dpdfnet2_48khz_hr.onnx`

GTCRN — примерно 523 КБ. Временный файл проверяется созданием нативной сессии,
после чего переименовывается. Повторная загрузка того же профиля блокируется.

### Что из исходного пожелания пока не реализовано

- Захват двух отдельных физических микрофонов и калиброванное фазовое вычитание.
  Текущие AudioRecord-тракты — моно; CHANNEL_IN_STEREO сам по себе не доказывает
  наличие независимого шумового reference-канала.
- DeepFilterNet3, отдельный De-Reverb и восстановление утраченного тембра.
  Studio использует поддерживаемый данным AAR DPDFNet, не выдаёт его за DFN3.
- Два offline-прохода по целой записи перед отправкой. Сейчас Studio — два
  последовательных потоковых этапа: нейросеть и DSP-мастеринг.

GTCRN/DPDFNet — шумоподавление, не гарантированная идентификация говорящего:
посторонний голос может оставаться. Обещание «дикторская будка в любом метро»
не является проверенным свойством этих моделей.

## Проверки

Добавлены тесты границ 1–16, сброса настроек, обратимого группирования по ID,
границ отправителя/времени/разделителя, счёта слов, PCM rate-adapter, отсутствия
изменений PCM при выключенной обработке и устойчивости мастеринга.

Доступный JVM/Robolectric-набор после UI/аудиоправок — 55 тестов без ошибок,
из них 29 hgram. Добавлены проверки двухсообщенческих цепочек, возрастающего
порядка истории, линейной ресэмплинг-интерполяции, удержания уровня при underrun
и повышения тихого сигнала ограниченным leveler.
Java/Kotlin и debug APK собраны. В libtmessages.49.so из APK проверены экспорты
трёх RNNoise JNI-функций и setRecordBitrate. Проверена подпись APK.

На телефоне необходимо проверить: картинки в выборе иконок/лаунчере, сохранение
положения чата при развороте, скорость при 1/4/16 запросах, отсутствие перегрузки
записи, задержку и синхронизацию аудио кружков, реальное качество RNNoise/GTCRN/DPDFNet.
Это не покрывается JVM-тестами и проверкой JNI-символов.
